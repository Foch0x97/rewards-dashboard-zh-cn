- 核对 `src` 和 `scripts` 中的日志调用、错误构造、接口日志辅助函数，以及动态拼接日志的格式化函数。

`log-catalog-zh-CN.js` 记录 **1,018 种源码文本**，每条有英文匹配模板、人工中文、数据保留位置及原文件位置。另有 **75 种**容器启动、常见诊断和之前 v5 格式的兼容文本。多行命令帮助和命令行表格不是任务运行日志，未混入该计数。

`log-vocabulary-zh-CN.js` 另外列出字段、登录状态、任务原因与阶段标签。日志不是只翻译外层句子：动态原因继续匹配中文规则，运行计划 JSON 递归展开中文字段，堆栈逐行展示。邮箱、搜索词、文章标题、网址、错误码、脚本参数名、函数名和代码路径是实际数据，保留其内容便于核对。

## 验证

```sh
node scripts/check.mjs
node --test tests/*.test.mjs
```

`tests/log-source-coverage.test.mjs` 逐条核对 1,093 种模板，检查插入的数据没有丢失；另检查真实格式中的账号结果、积分、嵌套失败原因、阅读进度、后台浏览上报、视觉搜索、JSON、调用堆栈，以及英文日志和通知输入保持原样。

`scripts/audit-log-coverage.mjs` 可只读扫描新的上游源码，列出缺失文本。它需要审计工具 TypeScript 的编译器文件路径；生产面板不需要安装 TypeScript：

```sh
node scripts/audit-log-coverage.mjs <上游源码目录> <typescript.js绝对路径>
```

匹配到了所有静态模板不等于所有动态响应都已验证。因此上游修订号变化时，即使未发现新句子，审计命令仍返回非零状态，要求人工复查动态值、格式化函数和任务结果含义。服务端临时返回的新诊断不会再被替换成空泛提示或丢弃；应依据原始内容补入目录，而不是伪造原因。

这些是源码与本地回归检查，不代表已连接或更新任何 NAS，也不代表已实际跑完积分任务。脚本原始输出、SSE、数据库和通知筛选输入均未改写。
